# ciao! — закрытая облачная версия

В комплекте: `index.html` (сохранённый дизайн v4), `config.js` (публичная конфигурация Supabase), `schema.sql` (таблицы, RLS и атомарная запись с контролем версий).

## 1. Резервная копия
В старой локальной версии откройте «Все проекты» → «Скачать резервную копию JSON». Сохраните файл в надёжном месте. **Не публикуйте JSON в GitHub или Vercel:** в нём могут быть личные данные.

## 2. Supabase
1. Создайте проект в https://supabase.com/dashboard.
2. В SQL Editor выполните `schema.sql`.
3. В Authentication → Providers → Email включите Email/Password. Отключите публичную регистрацию (Allow new users to sign up = OFF).
4. В Authentication → Users создайте или пригласите ровно двух пользователей. При приглашении по email потребуется настройка SMTP для надёжной доставки; альтернативно администратор может создать пользователей с временными паролями и передать их защищённым способом. Не отправляйте пароли в чат.
5. Скопируйте UUID каждого пользователя из Authentication → Users. В SQL Editor выполните (подставив реальные UUID):

```sql
insert into public.ciao_members(user_id, display_name) values
('UUID_КАТИ', 'Катя'),
('UUID_БОГДАНА', 'Богдан')
on conflict (user_id) do update set display_name=excluded.display_name;
```

6. Для мгновенных обновлений включите таблицу `public.ciao_workspace` в публикацию `supabase_realtime` через Database → Publications (или через SQL: `alter publication supabase_realtime add table public.ciao_workspace;`, если ещё не добавлена).
7. В Project Settings → API скопируйте Project URL и **publishable key** (или legacy anon key). Впишите их в `config.js`. **Не используйте `service_role`, secret key или пароль базы в браузерном файле.**

## 3. Vercel
1. Создайте приватный GitHub-репозиторий с `index.html`, `config.js`, `schema.sql` и `README.md` (SQL можно оставить локально). НЕ загружайте резервный JSON.
2. В https://vercel.com → Add New → Project импортируйте репозиторий.
3. Framework Preset: **Other**, Root Directory: корень, Build Command: пусто, Output Directory: пусто. Статические файлы будут опубликованы как есть.
4. Нажмите Deploy. Сайт получит адрес `*.vercel.app`.
5. Откройте адрес, войдите под одним из двух аккаунтов. Незарегистрированный пользователь не должен получить доступ.

## 4. Перенос JSON
1. Войдите на облачный сайт под Катей.
2. Откройте «Все проекты» → «Импортировать JSON» и выберите сохранённую резервную копию.
3. Подтвердите замену данных. После импорта проверьте проекты, календарь, финансы и заметки.
4. Войдите с другого устройства под Богданом и проверьте отображение данных.

## 5. Совместная работа и ограничения
- При изменениях приложение записывает весь снимок данных с проверкой версии. Если два человека меняют данные одновременно, вместо тихой перезаписи выводится предупреждение о конфликте. Перед обновлением страницы скопируйте несохранённую правку.
- Вкладки с одним аккаунтом и одновременная правка могут также конфликтовать. Это первая облачная версия, **не** полноценный построчный редактор.
- Синхронизация обновлений между устройствами требует включённого Supabase Realtime. Если изменения не появились, обновите страницу.
- Для серьёзного роста проекта рекомендуется разнести события, заметки, финансы и проекты в отдельные таблицы и добавить историю изменений.
- Встроенные фото мудборда находятся внутри HTML, а не в публичной отдельной папке. Проверьте права на их публикацию.
- Авторство идеи хранится в карточке проекта и не зависит от учётной записи редактора.
- Резервные копии создавайте регулярно. Supabase free tier имеет ограничения и условия активности.
- Для двух аккаунтов **не** нужен открытый signup. Удаление строки из `ciao_members` сразу отзовёт доступ к рабочей базе (после обновления сессии/страницы).

## Проверка перед реальной работой
- Вход под двумя приглашёнными пользователями работает.
- Третий пользователь не может прочитать `ciao_workspace`.
- Изменения сохраняются после перезагрузки.
- JSON-импорт успешно переносит данные.
- Финансовые расчёты корректны.
- Сохранена копия JSON вне сайта.

**Важно:** сайт подготовлен к публикации, но ещё не развёрнут и не подключён к вашему реальному Supabase. Для запуска нужны ваши действия в двух сервисах.
